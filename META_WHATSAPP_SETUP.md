## Почему уходим со шлюза

WhatsApp дважды принудительно разлогинил привязанный номер — 22:14 и 04:18,
второй раз сразу после отправки постороннему номеру. В логах `args: LOGOUT`:
это не сбой, а реакция на рассылку кодов с обычного аккаунта. Пересканирование
QR лечит на часы и приближает полный бан номера.

У Cloud API сессии нет вообще, разлогинивать нечего.

## 1. Что нужно приготовить заранее

| Что | Зачем |
|---|---|
| Аккаунт Facebook | вход в Meta Business |
| Документы компании | верификация бизнеса (свидетельство, реквизиты) |
| **Отдельный номер телефона** | станет номером отправителя |
| Банковская карта | оплата за сообщения, ~$1–5/мес при текущем объёме |

**Про номер — важно.** Он должен быть:

- **не привязан ни к какому WhatsApp** — ни к обычному, ни к Business. Если на
  нём стоит WhatsApp, его придётся сначала удалить, и переписка пропадёт;
- способен принять SMS или звонок для подтверждения;
- не тот, что сейчас в шлюзе (`+996222226070`) — иначе потеряешь переписку на нём.

Проще всего взять новую сим-карту под это.

## 2. Регистрация по шагам

### 2.1 Meta Business

1. <https://business.facebook.com> → создать бизнес-аккаунт.
2. Настройки → **Безопасность** → **Верификация бизнеса** → подать документы.
   Проверка занимает от суток до нескольких дней.

Без верификации отправка ограничена тестовым режимом: слать можно только на
номера, добавленные вручную. Для клиентов не годится.

### 2.2 Приложение и номер

> **Главная ловушка.** Вместе с новым приложением Meta автоматически выдаёт
> песочницу: тестовый номер вида `+1 555-…` («Test Number») и тестовый
> бизнес-аккаунт («Test WhatsApp Business Account»). Быстрый старт из
> документации работает именно на них, и кажется, что всё готово.
>
> В песочнице нельзя ничего из того, что нам нужно:
> - слать можно **только на 5 номеров**, добавленных вручную в консоли;
> - **свои шаблоны создавать нельзя** — API отвечает «У этого бизнес-аккаунта
>   WhatsApp нет разрешения на создание шаблонов сообщений» (код 10/2388185),
>   доступны только образцы Meta (`hello_world`, `jaspers_market_*`);
> - верификация бизнеса при этом может показывать `verified` — это про
>   компанию, а не про песочницу.
>
> Нужен **настоящий** бизнес-аккаунт и **свой** номер. Тестовые не
> «прогреваются» и в боевые не превращаются.

1. <https://developers.facebook.com> → **Мои приложения** → **Создать** →
   тип **Business**.
2. В приложении добавить продукт **WhatsApp**.
3. Привязать **свой** бизнес-аккаунт (не «Test WhatsApp Business Account»).
4. **Add phone number** → ввести **свой** номер → подтвердить кодом из
   SMS/звонка. После этого в списке номеров появится он, а не `+1 555-…`.

После этого на странице WhatsApp → API Setup появятся:

- **Phone number ID** — длинное число, это НЕ сам номер телефона;
- **WhatsApp Business Account ID**.

Запиши оба.

### 2.3 Постоянный токен

Временный токен на странице живёт сутки — для прода не подходит.

1. Meta Business → **Настройки** → **Пользователи** → **Системные пользователи**.
2. Создать системного пользователя с ролью **Admin**.
3. **Назначить активы** → выбрать приложение и WhatsApp-аккаунт → полный доступ.
4. **Создать токен** → права `whatsapp_business_messaging` и
   `whatsapp_business_management` → **срок: бессрочно**.

Токен показывается один раз — сохрани сразу.

> Токен со страницы **API Setup** для прода не годится: он временный и умирает
> в тот же день. Проверить свой можно так — если `expires_at` не `0`, токен
> временный:
>
> ```bash
> curl -s "https://graph.facebook.com/v25.0/debug_token?input_token=ТОКЕН&access_token=ТОКЕН"
> ```

### 2.4 Шаблон authentication

Meta → **WhatsApp Manager** → **Шаблоны сообщений** → **Создать**.

- Категория: **Аутентификация**
- Имя: `otp_code`
- Языки: **русский** (`ru`), при желании ещё `ky` / `en_US`
- Включить: **кнопку «Копировать код»**
- Включить: приписку о безопасности
- Срок действия в футере: **5 минут** — столько живёт код у нас

**Текст менять нельзя.** Он фиксирован Meta и переведён ей же: «*{{1}}* — ваш
код подтверждения». Настраиваются только приписка, срок и кнопка. Наш нынешний
текст с «CARGO» в Cloud API не переносится — имя отправителя клиент увидит из
профиля бизнеса, а не из текста.

Модерация — обычно несколько часов, иногда до суток.

## 3. Что вписать в `.env` на сервере

```bash
WHATSAPP_PROVIDER=meta
META_WA_PHONE_NUMBER_ID=<Phone number ID из 2.2>
META_WA_TOKEN=<постоянный токен из 2.3>
META_WA_TEMPLATE=cargo_otp
META_WA_LANG=ru
META_WA_API_VERSION=v25.0
META_WA_OTP_BUTTON=url        # url (one-tap) | copy_code
```

> **`META_WA_OTP_BUTTON` обязан совпадать с тем, что одобрено в шаблоне.**
> Код передаётся дважды — в теле и в кнопке, — и форма кнопки у этих типов
> разная. Перепутаешь: `#132018 Button at index 0 must be of type Url`,
> сообщение не уходит. Тип кнопки виден в WhatsApp Manager у шаблона.

`OTP_CHANNELS=whatsapp,sms` менять **не нужно** — канал остаётся «whatsapp»,
меняется только провайдер под ним. Приложение тоже не трогаем: в ответе
`send-code` по-прежнему приходит `channel: "whatsapp"`.

Затем:

```bash
systemctl restart cargo-web
```

Проверка — запросить код на свой номер и убедиться, что в ответе
`"channel":"whatsapp"`, а сообщение пришло с кнопкой «Копировать код».

## 4. После переезда

Когда Cloud API заработает, self-hosted шлюз убирается:

```bash
docker rm -f waha
systemctl disable --now waha-watchdog.timer
rm -rf /home/315cargo/waha-sessions
```

Страницу `/admin/whatsapp/` тоже можно снести — она нужна только для привязки
по QR, которой у Cloud API нет.

Спешить с этим не нужно: пока `WHATSAPP_PROVIDER=meta`, шлюз просто не
используется, и его можно держать выключенным про запас.

## 5. Сколько это стоит

Абонентской платы нет — платим только за доставленные сообщения. Ставка за
authentication в дешёвых регионах ~$0.01–0.03. При нынешних ~50 кодах в сутки
это **$1–5 в месяц**. Недоставленные не тарифицируются.

Это дешевле и Green API, и Wazzup, у которых подписка.

---

## 6. Что делать, если модерация шаблона откажет

Частые причины и что помогает:

- выбрана не та категория — должна быть именно **Аутентификация**, не Utility;
- имя шаблона занято или с недопустимыми символами — только латиница,
  цифры и `_`;
- бизнес не верифицирован — сначала §2.1.

Отказ не блокирует: шаблон правится и подаётся заново.

---

## 7. Пока идёт регистрация

Верификация и модерация займут от суток. Всё это время вход клиентам нужен, а
сейчас он не работает: WhatsApp разлогинен, SMS-аккаунт тестовый.

Варианты на переходный период:

1. **Пересканировать QR** на <https://315cargo.com/admin/whatsapp/> — заработает
   на часы, потом снова отвалится;
2. **Оплатить аккаунт Nikita** — SMS начнёт доставляться без правок в коде,
   `OTP_CHANNELS=whatsapp,sms` уже настроен.

Второе надёжнее и пригодится потом как запасной канал: когда Cloud API станет
основным, SMS останется страховкой на случай, если у клиента нет WhatsApp.
