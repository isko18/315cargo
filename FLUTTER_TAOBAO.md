# Taobao в Flutter — инструкция для клиента 315CARGO

Подключение Taobao сделано **по той же схеме, что и Pinduoduo**: логин в WebView,
перехват ответа со списком заказов, отправка сырых заказов на бэкенд. Бэкенд уже
готов — эндпоинты те же, отличается только префикс и формат перехватываемого
ответа.

Общую идею, ограничения (одна активная сессия, синк только при открытом
приложении) и код WebView смотрите в [FLUTTER_PINDUODUO.md](FLUTTER_PINDUODUO.md) —
здесь только то, что отличается.

---

## 1. Эндпоинты

Точно такие же, как у PDD, с префиксом `taobao` вместо `pinduoduo`:

| Метод | URL | Назначение |
|---|---|---|
| POST | `/api/integrations/taobao/connect/` | Пометить аккаунт подключённым (после логина в WebView) |
| POST | `/api/integrations/taobao/disconnect/` | Отключить |
| GET | `/api/integrations/taobao/status/` | Состояние подключения |
| POST | `/api/integrations/taobao/ingest/` | Прислать сырые заказы из WebView |
| POST | `/api/integrations/taobao/session-expired/` | Сообщить, что нужен повторный вход (`{"reason": "..."}`) |

Подключения независимы: клиент может быть подключён и к Pinduoduo, и к Taobao
одновременно — это разные аккаунты, разлогин одного не трогает другой.
В ответе появилось поле `marketplace` (`"pinduoduo"` / `"taobao"`).

## 2. Что перехватывать

У Taobao список заказов отдаёт **mtop**, а не обычный REST:

```
Страница:  https://h5.m.taobao.com/mlapp/olist.html
Запрос:    https://h5api.m.taobao.com/h5/mtop.taobao.order.queryboughtlistv2/1.0/…
```

Имя и версия проверены живым браузером (2026-08-08): сейчас это
**`mtop.taobao.order.queryboughtlistv2`, версия `1.0`**. Версия менялась и будет
меняться, поэтому **ловите по подстроке** `queryboughtlist` в URL без учёта
регистра — она входит и в `queryboughtlistv2`, и в будущие варианты.

Ответ завёрнут в JSONP (`mtopjsonp3({...})`) и имеет конверт:

```jsonc
mtopjsonp3({
  "api": "mtop.taobao.order.queryboughtlistv2",
  "v": "1.0",
  "ret": ["SUCCESS::接口调用成功"],   // статус вызова, см. ниже
  "data": { /* здесь заказы */ }
})
```

Заказы лежат внутри `data` — присылайте их как есть, **ничего не разбирая
на клиенте**: разбор живёт на сервере, чтобы правки не требовали пересборки
приложения. Можно прислать и весь ответ целиком — сервер найдёт список сам.

```jsonc
POST /api/integrations/taobao/ingest/
{
  "orders": [ /* сырые объекты заказов, как пришли от mtop */ ]
}
```

### Признак успешного логина

> ⚠️ **Не используйте `_tb_token_` и `cookie2`** как признак входа. Проверено
> вживую: Taobao ставит обе куки **анонимному** посетителю, ещё до логина.
> Проверка на них даёт ложное «вошёл» — приложение пометит аккаунт подключённым,
> а заказы не придут никогда.

Надёжных признака два, используйте оба:

1. **Кука `unb`** (идентификатор пользователя) на домене `.taobao.com` — её
   ставят только после успешного входа. Рядом обычно появляются `tracknick`
   и `lgc` (логин), их можно проверять как дополнительное подтверждение.
2. **Ответ mtop без ошибки сессии** — `ret[0]` начинается с `SUCCESS`, а не с
   `FAIL_SYS_SESSION_EXPIRED` (см. ниже). Это самая честная проверка: она
   говорит не «куки есть», а «заказы реально отдаются».

Дёргать `/connect/` стоит только после второго признака — тогда «подключён»
в панели означает, что синк действительно работает.

Куки живут на домене `.taobao.com`, сохранять и восстанавливать их нужно так же,
как описано в разделе 8 инструкции по PDD (session-cookie → постоянные,
`flush()` обязателен).

### Как поймать разлогин — важно

Протухшая сессия приходит **с кодом HTTP 200**, по статусу её не отличить.
Проверено живым браузером: без сессии `olist.html` редиректит на
`login.m.taobao.com/havanaone/login/login.htm`, а mtop отвечает так:

```jsonc
mtopjsonp3({"api":"mtop.taobao.order.queryboughtlistv2","data":{},
            "ret":["FAIL_SYS_SESSION_EXPIRED::Session过期"],"v":"1.0"})
```

Поэтому разлогин определяйте **по телу ответа**, а не только по редиректу:

```dart
// ret[0] вида FAIL_SYS_SESSION_EXPIRED / FAIL_SYS_TOKEN_EXOIRED / NEED_LOGIN
final ret = (json['ret'] as List?)?.first?.toString() ?? '';
if (ret.contains('SESSION_EXPIRED') || ret.contains('NEED_LOGIN')) {
  await api.markSessionExpired(reason: 'session_expired_mtop');
  return; // НЕ пытаться перелогиниться автоматически — это путь к бану
}
```

Такой ответ **не нужно** слать в `/ingest/`: заказов в нём нет.

## 3. Что сервер делает с сырым заказом

> ✅ **Раскладка подтверждена реальным ответом (2026-08-08).** Проверено на живом
> аккаунте с настоящим заказом — разбор извлёк номер, товар, сумму, количество
> и статус.

Ответ приходит **не списком заказов**, а деревом компонентов Ultron. Один заказ
размазан по нескольким компонентам, связанным общим id **в имени компонента**:

```jsonc
data: {
  data: {
    "Main_5127683545194034735":            { fields: { orderId: "5127…", orderStatus: "2_1" } },
    "sellerInfo_5127683545194034735":      { fields: { status: { text: "买家已付款" } } },
    "mainWaitSendShipTime_5127683545194034735": { fields: { title: "待发货" } },
    "item_5127683545194034735_1_1":        { fields: { item: { title: "…", quantity: 1,
                                                               priceInfo: { actualTotalFee: "34,83 сом" } } } },
    "pay_5127683545194034735/0":           { fields: { actualFee: { value: "61,83 сом" } } },
    "query3": {…}, "tab3": {…}, "feedStream": {…}   // служебные, не заказы
  },
  hierarchy: { root: "boughtlist4", structure: { … } },
  global:    { orderCount: 1 }
}
```

Отсюда сервер и собирает заказ:

| Поле заказа | Откуда |
|---|---|
| номер заказа | id в имени компонента `Main_<id>` (дублируется в `fields.orderId`) |
| статус | `sellerInfo_<id>.status.text` + заголовок блока ожидания (`待发货`, `待收货`) |
| сумма | `pay_<id>/0.actualFee.value`; если блока нет — сумма позиций `item.priceInfo.actualTotalFee` |
| товар, количество | `item_<id>_*.item.title` и `item.quantity` |
| трек-номер | поле вида `mailNo` в блоке логистики (появляется только у отправленного) |

**Две ловушки, на которых легко ошибиться:**

1. **Сумма приходит строкой с валютой**, а не числом: `"61,83 сом"` — валюта
   зависит от страны аккаунта, дробная часть отделена **запятой**, между числом
   и валютой неразрывный пробел. Сервер это разбирает; на клиенте сумму трогать
   не нужно.
2. **Служебные компоненты** (`query3`, `tab3`, `feedStream`, `emptyPage`) лежат
   рядом с заказами в том же словаре. Заказом считается только тот id, у
   которого есть компонент `Main_`.

**Что слать в `/ingest/`:** весь ответ целиком, одним элементом массива:

```jsonc
POST /api/integrations/taobao/ingest/
{ "orders": [ /* распарсенный JSON ответа queryboughtlistv2 */ ] }
```

Сервер сам развернёт дерево и достанет заказы. Разбирать что-либо на клиенте
не нужно — при смене формата правится только сервер.

Общие правила, одинаковые с PDD:

* отменённое и неоплаченное не сохраняем (`取消`, `待付款`, `待支付`, `退款`, `关闭`);
* `买家已付款` / `待发货` → «Оплачен», `已发货` / `待收货` → «Выкуплен»,
  `交易成功` → «Прибыл на склад в Китае»;
* по каждому заказу заводится посылка: по трек-номеру, а пока его нет — по
  номеру заказа (трек потом заменит временный идентификатор);
* дедуп по паре «источник + номер заказа», повторный `/ingest/` обновляет.

## 3.1. Как проверить раскладку полей на реальном ответе

Маппинг выше написан по документированной структуре mtop. Реальный ответ может
называть поля иначе — проверить это можно **до** того, как перехват допишут:
сохраните один ответ `queryboughtlist` в файл и прогоните на сервере

```bash
manage.py marketplace_parse_check --marketplace taobao --file orders.json
```

Команда **ничего не пишет в базу**, а показывает, что сервер извлёк бы из каждого
заказа: номер, товар, сумму, количество, статус, трек. Понимает и голый массив,
и полный ответ, и JSONP-обёртку `mtopjsonp1({...})`.

Если в конце написано «Раскладка полей совпала полностью» — можно смело
подключать перехват. Если «НЕ ОПОЗНАН» или пустые поля — пришлите вывод вместе
с одним сырым заказом, раскладка правится на сервере за минуты, без пересборки
приложения.

Ответ проще всего снять так: на телефоне вы уже залогинены в Taobao — откройте
`h5.m.taobao.com/mlapp/olist.html` в браузере с включённой отладкой (или
посмотрите лог Dio/консоль WebView), найдите запрос с `queryboughtlist`
и скопируйте тело ответа.

## 4. Оплата — важное ограничение

Как и в PDD, **оплатить заказ на Taobao из WebView не получится**: оплата идёт
через Alipay внутри приложения. Клиент из Кыргызстана платит либо картой,
привязанной к Alipay (нужна верификация, часто отказы банка), либо — что
проще — **заказывает через карго**, а карго выкупает сам.

Импорт заказов при этом остаётся полезным: он подхватывает то, что клиент
купил самостоятельно, и заводит посылки без ручного ввода треков.
