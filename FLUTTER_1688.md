# 1688 в Flutter — инструкция для клиента 315CARGO

Третья площадка на том же контракте, что Pinduoduo и Taobao: логин в WebView,
перехват ответа со списком заказов, отправка сырого ответа на бэкенд. Бэкенд
готов — отличается только префикс URL и что именно перехватывать.

Общую идею, ограничения (одна активная сессия, синк только при открытом
приложении, запрет авто-релогина) смотрите в
[FLUTTER_PINDUODUO.md](FLUTTER_PINDUODUO.md), формат ответа Alibaba — в
[FLUTTER_TAOBAO.md](FLUTTER_TAOBAO.md): у 1688 он такой же.

---

## 1. Эндпоинты

| Метод | URL | Назначение |
|---|---|---|
| POST | `/api/integrations/1688/connect/` | Пометить аккаунт подключённым |
| POST | `/api/integrations/1688/disconnect/` | Отключить |
| GET | `/api/integrations/1688/status/` | Состояние подключения |
| POST | `/api/integrations/1688/ingest/` | Прислать сырой ответ со списком заказов |
| POST | `/api/integrations/1688/session-expired/` | Сообщить, что нужен повторный вход |

Подключения трёх площадок независимы: клиент может быть подключён ко всем сразу,
разлогин одной не трогает остальные. В ответах поле `marketplace` = `"1688"`.

---

## 2. Что перехватывать

1688 работает на том же движке Alibaba, что и Taobao (проверено вживую
2026-08-09):

```
Хост API:  https://h5api.m.1688.com/h5/…
Движок:    mtop.alibaba.cbu.wireless.uniform.render.*
```

Ловите ответы mtop со **списком заказов покупателя** — по подстроке в URL,
без учёта регистра. Точное имя API у списка заказов снимите с реального
устройства: страница списка открывается только залогиненному, аноним
редиректится на главную (это и мешает определить имя заранее).

**Что делать:** повесьте тот же JS-хук, что и для PDD/Taobao, но ловите **все**
ответы с `h5api.m.1688.com`, у которых в теле есть `orderCount` или компоненты
с `orderId`. Пришлите один такой ответ — впишем точное имя API в документацию,
чтобы хук стал узким.

Ответ шлите **целиком**, ничего не разбирая:

```jsonc
POST /api/integrations/1688/ingest/
{ "orders": [ /* распарсенный JSON ответа mtop */ ] }
```

### Признак входа

Как и у Taobao — **не** по `_tb_token_`/`cookie2` (они есть и у анонима).
Ориентируйтесь на успешный ответ mtop: `ret[0]` начинается с `SUCCESS`, а не
с `FAIL_SYS_SESSION_EXPIRED`. По нему же ловите разлогин:

```dart
final ret = (json['ret'] as List?)?.first?.toString() ?? '';
if (ret.contains('SESSION_EXPIRED') || ret.contains('NEED_LOGIN')) {
  await api.markSessionExpired(marketplace: '1688', reason: 'session_expired_mtop');
  return; // НЕ перелогиниваться автоматически — это путь к бану
}
```

## 3. Как сервер разбирает заказ

Тем же кодом, что и Taobao: ответ приходит деревом компонентов, один заказ
размазан по нескольким узлам с общим id в имени компонента.

| Поле заказа | Откуда |
|---|---|
| номер заказа | id в имени компонента; если не вышло — поля `orderId`, `bizOrderId`, `orderNo`, `tradeId` |
| статус | `status.text` продавца + заголовки блоков ожидания |
| сумма | `actualFee.value` строкой с валютой; иначе сумма позиций |
| товар, количество | `item.title`, `item.quantity` |
| трек | поле вида `mailNo` где угодно в блоках заказа |

> ⚠️ **Раскладка полей 1688 ещё не сверена с реальным ответом.** Структура
> дерева у площадок Alibaba общая, но имена компонентов различаются, поэтому
> разбор написан терпимым: заказ сохранится, даже если часть полей не найдётся.
> Как только пришлёте настоящий ответ — доведём за минуты, **на сервере, без
> пересборки приложения**:
>
> ```bash
> manage.py marketplace_parse_check --marketplace 1688 --file orders.json
> ```
>
> Команда покажет, что сервер извлёк бы из каждого заказа, и ничего не запишет
> в базу.

**Статусы** — общий словарь с PDD и Taobao. Отменённые и неоплаченные заказы
теперь **сохраняются** (клиент видит их в приложении), но посылка под них не
заводится: `待付款` → «Оформлен», `交易关闭`/`已退款` → «Отменён»,
`买家已付款`/`待发货` → «Оплачен», `已发货`/`待收货` → «Выкуплен»,
`交易成功` → «Прибыл на склад в Китае».

## 4. Фильтр по площадке в приложении

У посылки есть источник — по нему делается фильтр «откуда посылка»:

```
GET /api/parcels/?source=1688
GET /api/parcels/?source_in=1688,taobao,pinduoduo
GET /api/parcels/                       ← все площадки
```

Поля `source` (`pinduoduo` / `taobao` / `1688` / `manual`) и
`source_display_name` (готовая подпись) приходят в каждой посылке.
