# Доставка по городу: переработка — готово

Ответ на «Доставка по городу: переработка». Всё из документа реализовано,
покрыто тестами (42 новых, старые проходят без правок) и описано в схеме
(`/api/schema/`). На прод ещё не выкачен — сообщим отдельно. Старые поля `parcel`, `address`, `price`, `tariff_title`,
`track_number` остались — установленные версии приложения не ломаются.

Базовый URL: `https://315cargo.com/api/`

---

## 1. Справочник точек

### Клиенту

```
GET /api/city-delivery-points/
```

Только активные точки карго клиента, в порядке, заданном карго. Пагинации нет —
точек единицы.

```json
[
  {
    "id": 1,
    "title": "Круговой Ак-Тилек, чайхана Ала-Тоо",
    "address": "",
    "work_hours": "",
    "is_active": true,
    "clients_count": 12
  }
]
```

`clients_count` — сколько клиентов уже возят сюда (без отменённых заявок).
Цены у точки нет: доставка бесплатная.

### Панели

```
GET    /api/manage/city-delivery-points/
POST   /api/manage/city-delivery-points/
PATCH  /api/manage/city-delivery-points/{id}/
DELETE /api/manage/city-delivery-points/{id}/
```

Права — как у `manage/pickup-points/` (вкладка `pickup`). `cargo` проставляется
по сотруднику, чужие точки — 404.

Поля: `title`, `address`, `work_hours`, `is_active`, `position` (порядок в
списке) и только для чтения: `clients_count`, `active_requests` (в работе),
`delivered_count` (доставлено за всё время), `created_at`, `updated_at`.

`DELETE`:
- **204** — на точку не было заявок, удалена;
- **200** и точка в ответе с `is_active: false` — заявки были, точку выключили.
  Клиент её больше не видит, а история заявок не ломается.

Шесть точек из приложения заводятся при выкатке. Дальше их можно менять из
панели без выпуска в сторы.

## 2. Заявка — на клиента

### Создание: `POST /api/city-delivery/`

```json
{
  "delivery_point": 1,
  "parcels": [101, 102],
  "recipient_name": "Иванов Иван",
  "recipient_phone": "+996700000001",
  "comment": "",
  "delivery_date": null,
  "delivery_time_slot": ""
}
```

Куда — одно из полей:
- `delivery_point` — точка из справочника;
- `suggested_point` — своя точка, если подходящей нет;
- `address` — старое поле, его шлют установленные версии.

Без всех трёх — 400 с текстом «Укажите, куда везти…» в `delivery_point`.

Ответы:

| Код | Когда |
|---|---|
| **201** | живой заявки не было — создана |
| **200** | живая заявка была, курьер её ещё не взял — обновлена этой анкетой целиком, `id` тот же |
| **409** | курьер уже взял заявку: `{"detail": "...", "id": 57}` — откройте заявку по `id` |
| **400** | чужая или закрытая точка; чужая, выданная или отменённая посылка; посылка уже едет с курьером |

Повторный POST — это полная анкета: поле, которого в нём нет, очищается. Чтобы
поменять одно поле, используйте PATCH.

### Ответ (тот же объект во всех методах)

```json
{
  "id": 57,
  "delivery_point": 1,
  "delivery_point_title": "Круговой Ак-Тилек, чайхана Ала-Тоо",
  "suggested_point": "",
  "address": "",
  "is_standing": false,
  "parcels": [
    {"id": 101, "track_number": "YT123", "status": "at_pickup_point",
     "status_display_name": "Прибыл в пункт выдачи", "weight": "0.600"}
  ],
  "parcels_count": 2,
  "total_weight_kg": "0.740",
  "parcel": 101,
  "track_number": "YT123",
  "tariff": null,
  "tariff_title": null,
  "price": "0.00",
  "status": "created",
  "status_display_name": "Создана",
  "...": "recipient_*, comment, delivery_date, delivery_time_slot, delivered_at, created_at, updated_at"
}
```

`parcel` и `track_number` — первая посылка из `parcels`; это для старых версий.

### Изменение и отмена

```
PATCH /api/city-delivery/{id}/          — точка, получатель, состав, дата
POST  /api/city-delivery/{id}/cancel/   — отмена
```

Оба работают, пока курьер не взял заявку (статусы `created`, `price_calculated`,
`accepted`). После этого оба вернут **409** с `id`. Если в PATCH прислать точку,
предложение снимется, и наоборот. После отмены следующий POST создаёт новую
заявку (201).

### Старые версии приложения

`{"parcel": 101, "address": "..."}` работает как раньше, с одним отличием:
посылка **добавляется** к живой заявке клиента, а не создаёт новую. Поэтому
второй такой POST вернёт 200 вместо 201. Если старая версия проверяет строго
201, скажите — подстроимся.

## 3. Постоянная заявка

POST **без `parcels`** создаёт постоянную заявку (`is_standing: true`) —
«всё моё везите сюда»:
- при создании забирает посылки клиента, которые уже лежат в ПВЗ;
- посылка, которая придёт в ПВЗ позже или найдёт хозяина уже в ПВЗ, сама
  попадёт в заявку. Это происходит, пока курьер её не взял;
- после доставки заявка открывается заново с той же точкой и получателем, с
  пустым составом. Клиент ничего не делает. Push об этом не отправляется.

Постоянную заявку можно задать и явно: `"is_standing": true` вместе с
`parcels`. Это значит «эти посылки и всё, что придёт».

## 4. Предложенные точки (панель)

```
GET  /api/manage/city-delivery/?suggested=true
GET  /api/manage/city-delivery-points/suggestions/
POST /api/manage/city-delivery-points/{id}/adopt-suggestions/   {"text": "Ош базар"}
```

`suggestions/` группирует живые заявки по месту без учёта регистра, пробелов
и «ё». Сверху — куда просит больше всего клиентов:

```json
[
  {
    "text": "Ошский рынок, вход с Кулатова",
    "clients_count": 2,
    "requests_count": 3,
    "request_ids": [12, 15, 19],
    "first_seen": "2026-10-01T09:12:00+06:00",
    "last_seen": "2026-10-06T18:40:00+06:00"
  }
]
```

`text` — самое частое написание у клиентов.

`adopt-suggestions/` переводит в точку все живые заявки с таким же текстом и
снимает у них предложение. Ответ: `{"updated": 2}`. Типичный путь: увидели
предложение → завели точку (`POST manage/city-delivery-points/`) →
`adopt-suggestions/` с текстом предложения.

`PATCH manage/city-delivery/{id}/` с `delivery_point` тоже снимает
предложение — для одной заявки.

В `GET /api/manage/dashboard/` добавлено поле `suggested_points_count` — сколько
живых заявок ждут, пока их предложение переведут в точку.

### Прочее в `manage/city-delivery/`

- Новые поля в ответе: `delivery_point`, `delivery_point_title`,
  `suggested_point`, `is_standing`, `parcels`, `parcels_count`,
  `total_weight_kg`.
- Новые фильтры: `?status=`, `?delivery_point=`, `?has_parcels=true` (скрыть
  пустые постоянные заявки — курьеру нечего везти).
- `in_delivery` и `delivered` теперь переводят **все** посылки заявки, а не
  одну.

## 5. Стоимость

Без тарифа цена **0**, а не «будет рассчитана». Push о создании пишет
«Бесплатно».

`POST /api/city-delivery/estimate/` принимает `parcels` или старое `parcel`, а
можно ничего: тогда вернётся 0.

Если карго заведёт свой тариф в панели, цена считается по суммарному весу
заявки.

## 8. Ответы на вопросы

**Делаем ли постоянные заявки?** Да, см. §3. Заявка собирает посылки до
отправки курьера и после доставки открывается заново.

**Повторный POST при живой заявке — обновляет её или возвращает 409?**
Обновляет (200, тот же `id`), пока курьер её не взял. Когда курьер уже взял —
409 с `id` заявки.

**Будет ли `adopt-suggestions/`?** Да, см. §4.
